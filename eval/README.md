# Quoba 평가

기획서의 성능 목표를 숫자로 확인하는 스크립트입니다. 정답을 미리 심어 둔 가상 팀플 대화로 측정합니다.

## 실행

```bash
node eval/generate.mjs           # 테스트 데이터 만들기 (eval/data)
node eval/score.mts              # 약속 규칙 + 검색 (로그인 불필요)
node eval/score.mts --answers    # AI 답변까지 (Dazzi 로그인 필요)
```

Node.js 24 이상이 필요합니다. 결과는 표로 출력되고 `eval/results/`에 JSON으로 저장됩니다.

## 테스트 데이터

- 4명(동키, 지민, 서연, 도윤)이 3개 채팅방에서 3개월 동안 나눈 대화 약 200개
- 정답이 있는 질문 100개: 담당자 40, 회의 장소 30, 준비물 30
- 정답이 없는 질문 20개 ("찾지 못했어요"라고 답해야 함)
- 내가 한 약속과 약속이 아닌 말(질문, 부탁, 거절)을 섞은 약속 라벨

## 지표와 목표

| 지표                        | 측정 방법                                              | 목표     |
| --------------------------- | ------------------------------------------------------ | -------- |
| Retrieval recall@5          | 정답 메시지가 검색 결과 상위 5개 안에 있는 질문의 비율 | 90% 이상 |
| Retrieval MRR               | 정답 메시지 순위의 역수 평균                           | 0.7 이상 |
| Answer accuracy             | 답변에 정답 키워드(담당자, 장소)가 들어간 비율         | 85% 이상 |
| "Not found" on unanswerable | 답이 없는 질문에 출처 없이 답한 비율                   | 90% 이상 |
| Promise recall              | 심어 둔 약속 중 찾아낸 비율                            | 85% 이상 |
| Promise precision           | 약속이라고 잡은 것 중 실제 약속의 비율                 | 80% 이상 |
| Promise due date accuracy   | 기한을 맞게 계산한 비율                                | 90% 이상 |
| Search latency (median)     | 검색 한 번에 걸린 시간의 중앙값                        | 1초 이내 |

## 한계

- 채팅 기록을 카카오톡 내보내기 형식의 텍스트 파일로 색인합니다. 실제 카카오톡 연결(lazykatok)과 묶는 단위가 다를 수 있어, 실사용자 테스트로 한 번 더 확인해야 합니다.
- 검색 결과 하나에 여러 줄이 묶여 있으면 정답 줄이 그 안에 있을 때 맞은 것으로 셉니다.
